# AI教育项目完善方案

## 目标

把当前项目从“功能验证型 MVP”推进到“可稳定演示、可持续迭代、具备上线基础”的产品版本。优先处理会阻塞协作和交付的问题：构建失败、敏感配置、权限边界、数据持久化、测试可靠性和学习闭环完整度。

## 当前判断

项目已经具备 AI 教学主线的雏形：登录、课程/知识点、流式讲解、白板、诊断、错题、复习、工具增强、动画/图片资源都已有代码或原型。主要短板不是“没有功能”，而是功能之间还没有沉淀成稳定闭环，工程基础也还停留在本地验证阶段。

## P0：先修交付阻塞

1. 前端构建必须稳定通过
   - 修复 Ant Design 类型导入路径。
   - 统一 SSE 和 axios 的 API baseURL。
   - 补齐流式事件里的媒体资源类型，避免 TypeScript 失真。

2. 敏感配置必须退出仓库
   - 轮换已经提交过的真实 API Key。
   - `.env` 只保留本地，不再纳入版本管理。
   - 补齐 `.env.example`，让新环境可复制配置。

3. 管理端权限边界必须一致
   - 管理端年级、科目、章节、知识点配置接口都必须要求管理员身份。
   - 统一捕获业务异常，避免真实冲突变成 500。

4. 测试入口必须可重复
   - 拆分本地单元测试和依赖 OpenSandbox/外部服务的集成测试。
   - 对异步测试统一使用 pytest-asyncio 标记或配置。
   - TTS、OpenSandbox、LLM 这类外部依赖默认 mock，真实调用放到显式集成测试。

## P1：打通学习闭环

1. 主路径收敛为一条链路
   - 学情诊断 -> 推荐知识点 -> AI 讲解 -> 互动提问 -> 掌握判定 -> 错题归因 -> 间隔复习。
   - 每个环节输出结构化结果，后续环节只依赖稳定字段，不直接解析自然语言。

2. 学生画像变成可运营数据
   - 记录知识点掌握度、错误类型、提示次数、复习间隔、学习时长、最近一次薄弱原因。
   - 后续推荐优先基于这些结构化数据，而不是只看当前会话。

3. 教学质量可评估
   - 为每轮教学记录：是否答对、是否需要追问、是否跳过、AI 是否调用工具、工具是否有效。
   - 建立最小指标面板：完成率、掌握率、错题复发率、平均讲解轮次、工具命中率。

## P2：工程化和上线基础

1. 正式数据层
   - 用 PostgreSQL 或 SQLite + Alembic 替代内存数据库和 JSON 文件。
   - 学习会话、诊断结果、错题本、复习计划、媒体资源都要有迁移和约束。

2. AI 服务治理
   - LLM 日志脱敏，生产环境不完整记录学生输入和系统提示词。
   - 增加超时、重试、降级模型、费用统计和 token 预算。
   - Prompt 版本化，关键教学策略要能回溯。

3. 部署环境
   - 前端通过 `VITE_API_BASE_URL` 配置 API 地址。
   - 后端生产环境启动时强制校验 `SECRET_KEY`、CORS、LLM API Key。
   - 生成媒体文件放对象存储或独立目录，避免混入代码仓库。

## 建议里程碑

### 第 1 周：可运行

- 前端 `npm run build` 通过。
- 后端基础 import/compile 通过。
- 管理端接口权限补齐。
- `.env.example` 和前端环境变量补齐。

### 第 2 周：可演示

- 主学习路径串联成稳定流程。
- 外部依赖测试全部 mock 化。
- 课程配置、学生学习、诊断、错题四个核心页面能连续演示。

### 第 3-4 周：可迭代

- 引入正式数据库迁移。
- 完成学习行为埋点和最小质量指标。
- 把工具增强从“能生成”改成“生成后可评价、可复用、可缓存”。

## 验收标准

- 前端构建无 TypeScript 错误。
- 后端启动不依赖本机绝对路径。
- 未登录用户不能访问学习接口，非管理员不能访问管理配置接口。
- 新开发者只靠 README 和 `.env.example` 能在本地跑起来。
- 一名学生可以完整走完一次：诊断、学习、回答、判定、错题、复习计划生成。
