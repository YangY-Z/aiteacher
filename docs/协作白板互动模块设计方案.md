# 协作白板互动模块设计方案

> 版本：v1.0\
> 日期：2026-05-11\
> 状态：设计阶段

***

## 一、项目背景

### 1.1 现有系统

当前AI教师系统已具备：

- **展示白板**：AI教师实时展示教学内容（知识点、公式、示例、图片）
- **流式对话**：AI教师与学生进行对话式教学
- **评估系统**：学习后的测验评估

### 1.2 需求目标

增加**协作白板互动**功能，让学生能够：

- 在白板上绘图、标注、解题
- AI实时观察并给予指导反馈
- 支持数学、物理、化学等理科综合学科

### 1.3 开发策略

采用**渐进式开发**：

- Phase 1：基础绘图 + 简单反馈（MVP）
- Phase 2：AI智能识别 + 实时批改
- Phase 3：学科专项工具 + 模拟实验

***

## 二、双白板协调机制

### 2.1 核心问题

系统存在两个白板：

| 白板类型 | 用途         | 控制方 |
| ---- | ---------- | --- |
| 展示白板 | AI教师展示教学内容 | AI  |
| 互动白板 | 学生绘图、解题、标注 | 学生  |

**关键问题**：如何在有限屏幕空间内协调两个白板的展示？

### 2.2 协调方案对比

#### 方案A：分离模式（独立窗口）

```
┌─────────────────────────────────────────────────┐
│                    Header                        │
├──────────────────────┬──────────────────────────┤
│                      │                          │
│    展示白板          │      互动白板            │
│    (AI内容)          │      (学生绘图)          │
│                      │                          │
│                      │                          │
├──────────────────────┴──────────────────────────┤
│                  聊天面板                        │
└─────────────────────────────────────────────────┘
```

**优点**：

- 两个白板独立，互不干扰
- 学生可以同时看到AI教学内容和自己绘图

**缺点**：

- 屏幕空间紧张，每个白板区域较小
- 视觉分散，学生注意力难以集中

***

#### 方案B：切换模式（推荐）

```
教学模式：                          互动模式：
┌─────────────────────────┐        ┌─────────────────────────┐
│                         │        │                         │
│      展示白板            │   ←→   │      互动白板            │
│      (AI内容)            │        │      (学生绘图)          │
│                         │        │                         │
├─────────────────────────┤        ├─────────────────────────┤
│        聊天面板          │        │        聊天面板          │
└─────────────────────────┘        └─────────────────────────┘
```

**优点**：

- 白板区域最大化，体验更好
- 符合教学流程（先讲解→再练习）
- 实现简单

**缺点**：

- 需要切换，不能同时查看

**切换触发时机**：

1. AI讲解阶段 → 展示白板
2. AI提问"请在白板上画出..." → 自动切换到互动白板
3. 学生提交绘图 → 切换回展示白板，AI展示批改结果

***

#### 方案C：叠加模式

```
┌─────────────────────────────────────────────────┐
│                                                 │
│    展示白板（背景层）                            │
│    ┌─────────────────────────────────────┐     │
│    │  互动白板（透明层，叠加在上面）       │     │
│    │  学生可以在AI内容上标注、补充        │     │
│    └─────────────────────────────────────┘     │
│                                                 │
├─────────────────────────────────────────────────┤
│                  聊天面板                        │
└─────────────────────────────────────────────────┘
```

**优点**：

- 学生可以直接在AI内容上操作
- 适合标注、补充类互动

**缺点**：

- 实现复杂度高
- 可能遮挡AI内容
- 不适合完全独立的绘图任务

***

#### 方案D：分时复用模式（最终推荐）

结合方案B和方案C的优点：

```
┌─────────────────────────────────────────────────────────────┐
│                         Header                               │
│  [展示白板] [互动白板]                    ← 模式切换Tab      │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│                    白板主区域                                │
│                                                             │
│   根据当前模式显示：                                         │
│   - 展示模式：AI教学内容                                     │
│   - 互动模式：学生绘图区（可选背景模板）                      │
│   - 标注模式：展示白板内容 + 学生标注层                       │
│                                                             │
├─────────────────────────────────────────────────────────────┤
│                     浮动聊天面板                              │
└─────────────────────────────────────────────────────────────┘
```

**三种模式**：

| 模式   | 描述               | 使用场景        |
| ---- | ---------------- | ----------- |
| 展示模式 | 只读，显示AI教学内容      | AI讲解知识点     |
| 互动模式 | 可编辑，学生独立绘图       | AI要求学生画图、解题 |
| 标注模式 | 半透明叠加，学生在AI内容上标注 | AI要求学生补充、修改 |

### 2.3 推荐方案：分时复用 + 模式切换

**设计决策**：

1. **统一白板组件**：一个白板组件，支持多种模式
2. **状态驱动**：根据教学阶段自动切换模式
3. **手动切换**：学生也可以手动切换查看
4. **历史保留**：切换模式时保留之前的内容

**状态管理**：


### 2.4 模式切换流程

```
教学流程                          白板模式
───────────────────────────────────────────────
AI开始讲解知识点                  → 展示模式
    ↓
AI在白板展示公式、图示
    ↓
AI提问："请在坐标系中画出y=2x+1"
    ↓                               → 互动模式
系统自动切换到互动白板
    ↓
学生绘图...
    ↓
学生点击"提交"
    ↓                               → 展示模式
AI分析绘图，展示批改结果
    ↓
AI继续讲解或纠正
```

### 3.4 状态管理

```typescript
// store/interactiveStore.ts

import { create } from 'zustand';

interface InteractiveState {
  // 白板模式
  mode: WhiteboardMode;
  setMode: (mode: WhiteboardMode) => void;
  
  // 绘图数据
  strokes: DrawingStroke[];
  addStroke: (stroke: DrawingStroke) => void;
  clearStrokes: () => void;
  undo: () => void;
  redo: () => void;
  
  // 当前工具
  currentTool: DrawingTool;
  setCurrentTool: (tool: DrawingTool) => void;
  
  // 工具配置
  penColor: string;
  penWidth: number;
  setPenColor: (color: string) => void;
  setPenWidth: (width: number) => void;
  
  // 模板
  currentTemplate: DrawingTemplate | null;
  setTemplate: (template: DrawingTemplate | null) => void;
  
  // AI反馈
  aiFeedback: AIFeedback | null;
  setAIFeedback: (feedback: AIFeedback | null) => void;
  
  // 提交状态
  isSubmitting: boolean;
  setSubmitting: (submitting: boolean) => void;
  
  // 历史记录（撤销/重做）
  history: DrawingStroke[][];
  historyIndex: number;
}

export const useInteractiveStore = create<InteractiveState>((set, get) => ({
  mode: 'display',
  setMode: (mode) => set({ mode }),
  
  strokes: [],
  addStroke: (stroke) => set((state) => ({
    strokes: [...state.strokes, stroke],
    history: [...state.history.slice(0, state.historyIndex + 1), [...state.strokes, stroke]],
    historyIndex: state.historyIndex + 1,
  })),
  clearStrokes: () => set({ strokes: [] }),
  
  undo: () => {
    const { historyIndex, history } = get();
    if (historyIndex > 0) {
      set({
        strokes: history[historyIndex - 1] || [],
        historyIndex: historyIndex - 1,
      });
    }
  },
  redo: () => {
    const { historyIndex, history } = get();
    if (historyIndex < history.length - 1) {
      set({
        strokes: history[historyIndex + 1],
        historyIndex: historyIndex + 1,
      });
    }
  },
  
  currentTool: 'pen',
  setCurrentTool: (tool) => set({ currentTool: tool }),
  
  penColor: '#000000',
  penWidth: 2,
  setPenColor: (color) => set({ penColor: color }),
  setPenWidth: (width) => set({ penWidth: width }),
  
  currentTemplate: null,
  setTemplate: (template) => set({ currentTemplate: template }),
  
  aiFeedback: null,
  setAIFeedback: (feedback) => set({ aiFeedback: feedback }),
  
  isSubmitting: false,
  setSubmitting: (submitting) => set({ isSubmitting: submitting }),
  
  history: [[]],
  historyIndex: 0,
}));
```

### 4.2 绘图分析服务

```python
# services/drawing_analyzer.py

class DrawingAnalyzer:
    """绘图分析服务"""
    
    async def analyze_drawing(
        self,
        image_data: str,
        task_type: str,
        context: dict,
    ) -> AIFeedback:
        """
        分析学生绘图
        
        Args:
            image_data: Base64编码的图片
            task_type: 任务类型（draw_function, draw_circuit等）
            context: 上下文（题目要求、正确答案等）
        
        Returns:
            AI反馈
        """
        # 1. 调用多模态LLM分析图片
        analysis = await self.llm_service.analyze_image(
            image_data,
            prompt=self._build_analysis_prompt(task_type, context),
        )
        
        # 2. 解析分析结果
        return self._parse_feedback(analysis)
    
    def _build_analysis_prompt(self, task_type: str, context: dict) -> str:
        """构建分析提示词"""
        return f"""
        你是一位理科教师，正在批改学生的绘图作业。
        
        任务类型：{task_type}
        题目要求：{context.get('instruction')}
        参考答案：{context.get('reference')}
        
        请分析学生的绘图：
        1. 是否正确
        2. 哪里做得好
        3. 哪里有问题
        4. 如何改进
        
        以JSON格式返回：
        {{
            "correct": true/false,
            "score": 0-100,
            "feedback": "详细反馈",
            "corrections": [
                {{"type": "highlight", "position": {{"x": 0, "y": 0}}, "content": "标注内容"}}
            ]
        }}
        """
```

| 图片导出  | Canvas API + html2canvas | 原生支持，成熟稳定              |
| 多模态AI | 通义千问VL / GPT-4V          | 支持图片理解                 |

***

## 八、风险与对策

| 风险     | 影响      | 对策                               |
| ------ | ------- | -------------------------------- |
| 屏幕空间不足 | 用户体验差   | 采用分时复用模式，最大化白板区域                 |
| 手写识别不准 | AI反馈质量差 | Phase 1 先用多模态LLM，Phase 2 集成专业OCR |
| 绘图数据量大 | 存储和传输压力 | 只存储笔迹数据，不存储图片；提交时才生成图片           |
| 移动端体验差 | 触控不精准   | 优先PC端，移动端后续优化                    |
