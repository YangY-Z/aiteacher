# 陪伴学习乔布斯式交互设计

## 设计判断

当前陪伴学习页的问题不是缺少信息，而是信息都在同一层级里出现：学生既看到课程进度、章节、知识地图、徽章，又缺少“我现在该继续哪里”的焦点。新方案把页面拆成两个体验层级：

```text
学习空间
  选择今天要进入的科目 / 课程

课程控制台
  聚焦一门课：继续学习、章节轨道、知识地图
```

## 体验原则

- 第一屏只强调一个主动作：继续当前最合适的学习内容。
- 科目不是文本列表，而是有视觉身份的学习入口。
- 选择器默认安静，只在用户要切换时展开。
- 进度优先用图形表达，文字只保留必要标签。
- 课程控制台不承担多科目总览，避免变成复杂仪表盘。

## 页面结构

### 学习空间

```text
今天继续哪一门？

[ 数学视觉卡 ]
一次函数
6%
[继续]

[ 英语视觉卡 ]
尚未开始

[ 物理视觉卡 ]
尚未开始
```

视觉卡不是大段说明，而是三个元素：

- 科目名
- 当前课程 / 最近学习点
- 进度图形 + 主按钮

### 课程控制台

```text
一次函数                         数学 / 初二

当前正在学：函数图像
本课程进度 6%
[继续学习]

章节轨道
[全部] [基础概念] [表达式] [图像] [应用]

知识地图
```

课程控制台保留章节筛选和知识地图，但顶部由“解释信息”变成“行动焦点”。

## 交互规则

- `/center` 默认进入学习空间。
- 学习空间点击课程后进入课程控制台。
- 课程控制台接收 `courseId`，不再硬编码 `MATH_JUNIOR_01`。
- 切换章节只影响当前页的知识地图和继续学习优先级，不改变后端学习进度。
- 进入学习页仍然携带 `kp_id`，白板和学习记录继续按知识点隔离。
- 最近进入的课程记录在前端本地，用于下次突出“继续”入口。

## 验收标准

- `/center` 默认不是直接进入知识地图，而是先看到学习空间。
- 学习空间不是纯文本列表，课程卡片有明确视觉身份和进度表达。
- 点击课程能进入对应课程控制台。
- 课程控制台仍可按章节筛选知识地图。
- 前端构建通过，浏览器检查没有明显布局挤压。
